# Reward Validation

Run `python tests/reward/run_all.py` before starting any LLM training to verify the reward function is correctly shaped. The decision tree is: **sanity** → if ordering holds, run **variance** → if stdev > 0.5, run **components** → if all three pass, run `baseline.py` to measure the random-policy mean reward over ~200 episodes; if the mean lands in [-0.5, +0.5] the reward is neither trivially achievable nor impossibly sparse, and training can begin. A sanity failure means one policy archetype is being rewarded incorrectly (compare per-step breakdowns to isolate whether progress, action-quality, penalty, or terminal reward is mis-shaped). A variance failure means all episodes score similarly, collapsing GRPO's relative-advantage signal to near zero — usually caused by health-stage weights that are too uniform, action-quality bonuses that are too small relative to the terminal reward, or terminal_reward that is too close to the random baseline. A component failure pinpoints a broken formula in `reward/components.py` and must be fixed before the other two checks are meaningful.
