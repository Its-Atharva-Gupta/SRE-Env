## Project Overview

This is an OpenEnv-compatible reinforcement learning environment where an LLM agent
acts as a Site Reliability Engineer (SRE). The agent SSHes into a broken Linux server,
diagnoses the fault using terminal commands, and fixes it. Reward is computed from
verified system state — not from the model's output text.

The agent receives:
- A one-line pager alert (e.g. "ALERT: nginx failed to restart after config push")
- SSH credentials to a sandboxed Docker container
- A step budget (default: 8 steps)

The agent outputs one shell command per step. The environment executes it and returns
real terminal output.

## `models.py`

Define three dataclasses using OpenEnv's base types.

### `SREObservation`
Fields:
- `terminal_output: str` — raw stdout+stderr from the last command
- `prompt: str` — the shell prompt line (e.g. `[sre@prod-01 ~]$`)
- `step: int` — current step number (1-indexed)
- `steps_remaining: int`
- `health_score: float` — current 0.0–1.0 system health (visible to agent)
- `alert: str` — the original pager alert, repeated every step for context

Inherits from `openenv.core.Observation`.

### `SREAction`
Fields:
- `command: str` — the shell command the agent wants to run. Single line only.

Inherits from `openenv.core.Action`. Add a validator that strips newlines and
truncates to 500 characters. Reject empty strings.

### `SREState` (server-side only, not exported)
Fields:
- `container_id: str`
- `fault_id: str`
- `ssh_port: int`
- `step: int`
- `prev_score: float`
- `prev_command: str`
- `used_diagnostics: set[str]`
- `alert: str`
- `done: bool`

Not an OpenEnv type — plain dataclass. Lives only in `server/sre_environment.py`.

## `client.py`

Implements `SREEnv(EnvClient)` from `openenv.core`.

### Constructor
Accepts standard OpenEnv kwargs. No extra config needed — everything is
server-side.

### `reset() -> SREObservation`
Calls the OpenEnv `/reset` endpoint. Returns the initial observation, which
contains:
- The alert message
- Output of the auto-run diagnostic suite (see server section)
- `step=0`, `health_score=0.0`

### `step(action: SREAction) -> tuple[SREObservation, float, bool, dict]`
Calls the OpenEnv `/step` endpoint with the action. Returns standard
(obs, reward, done, info) tuple. The `info` dict contains reward breakdown:
`r_progress`, `r_action`, `r_terminal`, `r_penalty`, `passing_stages`.

### `render() -> str`
Returns a pretty-printed string of the last observation for human inspection.
Format it like a real terminal session.

### `close()`
Calls `/close` endpoint to release the container back to the pool.

## `faults/registry.py`

Central registry of all fault definitions. Each fault is a dataclass:

```
FaultSpec:
    id: str
    tier: int                  # 1=easy, 2=medium, 3=hard
    alert: str                 # what the model sees
    inject_script: str         # path under faults/scripts/inject/
    health_stages: list[Stage] # see health.py
    process_checks: list       # layer 1 — see verifier.py
    integrity_checks: list     # layer 2
    functional_check: dict     # layer 3
    max_steps: int             # default 8
```

### Implemented Faults (minimum viable set — implement in this order)

**Tier 1**
- `nginx_stopped` — `pkill -9 nginx`, alert: "ALERT: HTTP 502 errors spiking"
- `log_permissions` — `chmod 000 /var/log/nginx/`, alert: "ALERT: nginx write errors"
- `missing_config` — delete `/etc/nginx/sites-enabled/default`

**Tier 2**
- `broken_nginx_config` — inject bad `listen BROKEN` line into nginx.conf
- `disk_full` — `dd` a 900MB dummy file into `/var/log/`
- `broken_symlink` — make `/usr/bin/python3` a dangling symlink
- `zombie_process` — fork bomb (limited), alert: "ALERT: process count anomaly"

**Tier 3**
- `bad_cron` — inject malformed cron syntax
- `multi_fault` — combine nginx_stopped + log_permissions simultaneously

### `FaultRegistry`
- `get(fault_id) -> FaultSpec`
- `sample(tier=None) -> FaultSpec` — random sample, optionally filtered by tier
- `all_ids() -> list[str]`

## `reward/health.py`

### `Stage` dataclass
```
name: str
weight: float       # weights across all stages must sum to 1.0
check_cmd: str      # shell command; exit 0 = stage passing
```

### `HealthScorer`
Single method:
```
score(container, fault_id) -> tuple[float, list[str]]
```
Returns `(total_score_0_to_1, list_of_passing_stage_names)`.

Runs each stage's `check_cmd` via `container.exec_run`. Adds `weight` for each
passing stage. Clamps result to `[0.0, 1.0]`.

Stage definitions live in `FaultSpec.health_stages` from the registry —
`HealthScorer` is fault-agnostic.

**Important**: keep each check_cmd to a single shell one-liner. No scripts,
no file reads — just `systemctl is-active`, `pgrep`, `test -f`, `ss -tlnp | grep`,
`curl -sf`, `df` with awk. These must finish in < 100ms.

## `reward/verifier.py`

Three-layer verification. Only runs when `health_score >= 1.0`.

### `Verifier`
Constructor: `(container, fault_spec: FaultSpec)`

Method: `verify() -> tuple[bool, str]`

Runs layers sequentially. Short-circuits on first failure.

**Layer 1 — Process State** (`_check_process_state`)
- Commands from `fault_spec.process_checks`
- Each is `(cmd: str, failure_reason: str)`
- All must pass (exit 0)
- Fast: systemctl, pgrep, test, ss

**Layer 2 — Integrity** (`_check_integrity`)
- Commands from `fault_spec.integrity_checks`
- Guards against degenerate fixes (deleting config, chmod 777 everything, etc.)
- Check that required files exist, ownership is correct, configs are parseable
- Must include a `grep` check that the specific bad content is gone

**Layer 3 — Functional** (`_check_functional`)
- From `fault_spec.functional_check`: `{cmd, expected_exit, output_validator}`
- `output_validator` is a lambda on stdout string
- For nginx faults: `curl` returning HTTP 200/301
- For disk faults: can write a 10MB test file
- For permission faults: nginx can actually append to access.log after a request
- This is the most expensive check — may take 2–5s (curl timeout)

Return value: `(True, "all checks passed")` or `(False, "layer2 failed: <reason>")`

## `reward/components.py`

Pure functions. No state. No container access.

### `progress_reward(prev: float, curr: float) -> float`
```
delta = curr - prev
if delta > 0: return delta * 2.0
if delta < 0: return delta * 1.0
return 0.0
```

### `action_quality_reward(command: str, used: set[str]) -> float`
Regex patterns mapped to one-time bonus values. Modifies `used` in place.

Pattern → bonus mapping (implement exactly these values):
```
journalctl          → 0.08
systemctl status    → 0.08
systemctl --failed  → 0.06
nginx -t            → 0.07
tail.*log           → 0.05
cat.*log            → 0.05
ss -|netstat        → 0.04
df -|du -           → 0.04
ps aux|ps -ef       → 0.04
dmesg               → 0.05
ls -la|ls -l        → 0.02
cat /etc/           → 0.03
grep.*conf          → 0.03
```

One-time only per episode. Pattern match is `re.search`, not exact.

### `penalty(command: str, prev_command: str) -> tuple[float, bool]`

Returns `(reward_delta, episode_over)`.

Step cost: `-0.02` always.

Repeat penalty: `-0.15` if `command.strip() == prev_command.strip()`.

Destructive commands (set `episode_over=True`, return `-2.0`):
```
"rm -rf /"
"rm -rf /*"
"mkfs"
"dd if=/dev/zero of=/dev/sd"
":(){:|:&};:"
"chmod -R 000 /"
"> /etc/passwd"
```

Check with `any(d in command for d in DESTRUCTIVE)`.

Also flag but do NOT terminate (just `-0.5`) for:
```
"vim"   "nano"   "emacs"   "less"   "more"
```
These are interactive and will hang the exec — penalize but recover gracefully
by killing the exec after timeout.

### `terminal_reward(steps_taken: int, max_steps: int) -> float`
Only called when `Verifier.verify()` returns True.
```
base = 2.0
efficiency_bonus = (steps_remaining / max_steps) * 1.0   # max +1.0
layer_bonus = 0.5                                          # flat, full verify passed
return base + efficiency_bonus + layer_bonus
```
Range: 2.5 (slow, last step) to 3.5 (fast, first step — unlikely but possible).

## `reward/engine.py`

### `RewardEngine`
Stateful per-episode. Orchestrates all components.

Constructor: `(fault_spec: FaultSpec, max_steps: int = 8)`

Initializes: `prev_score=0.0`, `prev_command=""`, `used_diagnostics=set()`,
`steps=0`

Method: `step(command: str, container) -> tuple[float, bool, dict]`

Logic:
1. Increment `self.steps`
2. Call `penalty()` — if destroyed, return immediately
3. Call `HealthScorer.score()` to get `curr_score`
4. Call `progress_reward(self.prev_score, curr_score)`
5. Call `action_quality_reward(command, self.used_diagnostics)`
6. If `curr_score >= 1.0`: instantiate `Verifier`, call `.verify()`
   - If verified: call `terminal_reward()`, set `done=True`
   - If not verified (false positive from health score): `r_terminal = 0`, continue
7. If `self.steps >= max_steps`: `done = True`
8. Sum all components → `total`
9. Update `self.prev_score`, `self.prev_command`
10. Return `(total, done, info_dict)`

The `info_dict` must contain: `health_score`, `passing_stages`, `r_progress`,
`r_action`, `r_terminal`, `r_penalty`, `total`, `verified`, `steps`.

## `sandbox/pool.py`

### `ContainerPool`
Pre-warms Docker containers so episode reset is near-instant.

Constructor: `(pool_size: int = 8, image: str = "sre-server:latest")`

On init: starts `pool_size` containers in background threads. Each container
runs the server image with SSH daemon. Stores `(container, ssh_port)` tuples
in a `queue.Queue`.

Method: `acquire() -> tuple[Container, int]`
Pops from queue. Immediately spawns a replacement in a background thread.

Method: `release(container)`
Kills and removes the container. Does NOT return to pool — pool refills itself.

Method: `shutdown()`
Kills all containers. Call in cleanup.

Container run config:
```
image: sre-server:latest
detach: True
tty: True
ports: {"22/tcp": None}      # random host port
mem_limit: "512m"
cpu_quota: 50000              # 0.5 CPU
network_mode: "bridge"
remove: True                  # auto-remove on kill
```

After `containers.run()`, call `container.reload()` to get the assigned port from
`container.ports["22/tcp"][0]["HostPort"]`.

Wait for SSH readiness by polling `container.exec_run("test -f /tmp/ready")`
with 100ms sleep, 15s timeout.

## `sandbox/ssh.py`

### `SSHSession`
Thin wrapper around paramiko.

Constructor: `(host: str, port: int, user: str = "sre", password: str = "fix123")`
Connects on init. Set `timeout=10` on `connect()`.

Method: `run(command: str, timeout: int = 10) -> tuple[str, int]`
Uses `exec_command`. Returns `(stdout + stderr, exit_code)`.
Always decode with `errors="replace"`.
Strip ANSI escape codes from output before returning
(use `re.sub(r'\x1b\[[0-9;]*m', '', output)`).

Method: `close()`

Do NOT maintain persistent shell state (no channel reuse). Each `run()` is a
fresh `exec_command` call. This means `cd` does not persist — handle this by
always running commands from `/home/sre` or having agent use absolute paths.
This is intentional: it keeps the interface stateless and prevents the agent
from getting confused by cwd state.

## `server/sre_environment.py`

Implements `SREEnvironment(Environment)` from `openenv.core`.

### `reset(config: dict = None) -> SREObservation`
1. Pull a container from `ContainerPool.acquire()`
2. Sample a fault from `FaultRegistry` (respect tier from config if provided)
3. Inject the fault: `container.exec_run(f"bash /faults/inject/{fault.inject_script}")`
4. Create `SSHSession` to the container
5. Create `RewardEngine(fault_spec)`
6. Store all in `SREState`
7. Run auto-diagnostic suite:
   ```bash
   systemctl --failed --no-pager; df -h; uptime; whoami
   ```
8. Return `SREObservation` with the alert + diagnostic output

### `step(action: SREAction) -> tuple[SREObservation, float, bool, dict]`
1. Validate command (not empty, not multi-line)
2. Handle interactive commands (vim, nano, etc.): return fake error message,
   don't actually run them. The penalty is applied in `RewardEngine`.
3. `SSHSession.run(action.command, timeout=10)` — wrap in try/except TimeoutError
4. `RewardEngine.step(command, container)`
5. Format output as terminal string: `output + "\n[sre@prod-01]$ "`
6. Update `SREState.step`, `.prev_command`
7. If `done`: `ContainerPool.release(container)`, `SSHSession.close()`
8. Return `(obs, reward, done, info)`

### `close()`
Release container and close SSH if episode didn't finish naturally.

## Critical Constraints

**Never** let the model's text output determine reward. Only system state does.

**Never** run the functional check (curl, dd) unless health score is exactly 1.0.
It is too slow to run on every step.

**Always** pre-warm containers. Cold container startup is ~2s and will bottleneck
training throughput.

**Always** set exec timeouts. A hanging command (interactive editor, sleep infinity)
must not stall the training loop. Default timeout: 10s. Kill and penalize.

**Always** log the full info dict per step. You will need it to debug reward shaping.

**Degenerate fixes to guard against in Layer 2:**
- Deleting config files instead of fixing them
- `chmod 777 /` to fix permission issues
- `killall` on processes that shouldn't be killed
- Writing a fake response server instead of fixing nginx

Each fault's integrity checks must specifically guard against the most obvious
degenerate fix for that fault.

## Reward Summary Table

| Component | Typical Range | Notes |
|---|---|---|
| `progress_reward` | -0.5 to +0.8 | Per step, based on health delta |
| `action_quality` | 0 to +0.08 | One-time per diagnostic class |
| `step_cost` | -0.02 | Every step |
| `repeat_penalty` | -0.15 | Exact command repeat |
| `interactive_penalty` | -0.50 | vim/nano/less etc |

**Target episode reward for a well-trained model:** +2.5 to +3.5
**Random policy baseline:** -0.5 to +0.3
**Degenerate (spam ls) policy:** -1.0 to -0.2
